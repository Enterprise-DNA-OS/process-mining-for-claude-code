# Why there is no front end

An event history already records which case moved, what happened and when. This build puts that history beside the process owner's rules and improvement work, then answers the weekly questions from the database.

The five weekly rituals are reviewing cases, finding long elapsed gaps, checking repeated steps, reviewing checkpoints and assigning improvements. Claude Code, Codex, OpenCode or Cursor reads the same commands and presents the result. Read-only HTML views and documents give the owner something to inspect or print.

IBM Process Mining has a broader hosted platform. This build does not include interactive process maps, simulation, object-centric models, desktop task capture, streaming connectors, mobile screens or automated process execution. It does not replace those capabilities by renaming a report. It is useful for an operator who can supply a complete exported event history and wants analysis plus accountable follow-up. Enterprise DNA can scope the required connections and screens around that work.

There is no web server, form or button that changes data. The database and CLI are the operating system for this desk. One database belongs to one organisation. Authentication, scoped roles, backup and restore, deployment security and ongoing operation need to be configured for a shared installation.
